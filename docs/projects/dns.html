Investigating a DNS service failure

Course exerciseNetwork analysis · Troubleshooting

Repeated DNS queries receive ICMP errors. The useful first step is to identify what failed, then test possible causes.

Finding

The original report describes DNS requests to 203.0.113.2 on UDP port 53 and the returned message ICMP 203.0.113.2 udp port 53 unreachable.

This supports a failure to reach the requested UDP service. It does not establish a DDoS attack or prove that the entire host is down.

Possible explanations and checks

HypothesisWhat to check next
DNS service is stopped or not listening on the expected interface.Service state, listening sockets, application logs and recent configuration changes.
The client is using an incorrect DNS destination.Resolver configuration and the intended DNS server address.
A network policy explicitly rejects the request.Firewall rules, reject logs and the origin of the ICMP response.
A wider availability incident is affecting the service.Other clients' results, traffic volume, resource use and service health over the same period.

Each check is a proposed investigation step. No service restoration or root-cause confirmation is claimed here.

Review of the original report

The initial report called the response an “ICMP echo reply” and suggested DDoS as the likely cause. This revision corrects both points.

In IPv4, port unreachable is ICMP type 3, code 3. An echo reply is a different message type. The described errors alone are insufficient to infer distributed attack traffic.

The revised conclusion is narrower: DNS resolution is failing, the requested UDP service is reported unreachable, and the cause requires further investigation.
