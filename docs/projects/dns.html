Investigating a DNS service failure

Google course exerciseDNS · UDP · ICMP

DNS queries return a port-unreachable error. I reviewed what that message tells us and corrected two mistakes in my original report.

What failed

Requests to 203.0.113.2 on UDP port 53 received ICMP 203.0.113.2 udp port 53 unreachable. The requested UDP service was unreachable. This message alone doesn't establish DDoS or show that the whole host is down.

Details from the report

ItemRecorded value
Client192.51.100.15
Destination203.0.113.2:53, UDP
ResponseICMP destination unreachable, port unreachable
Times13:24:32.192571, 13:26:32.192571, 13:28:32.192571

Checks to narrow down the cause

  • Check whether DNS is running and listening on the right interface.
  • Confirm the client's resolver settings and intended server address.
  • Look for firewall rejects and identify where the ICMP reply came from.
  • Compare other clients' results, traffic volume and server health at the same times.

These are proposed checks. This note uses the report rather than a separate packet capture, and the cause hasn't been confirmed.

Correction to the original report

I originally called the response an ICMP echo reply and suggested DDoS. Port unreachable is ICMP type 3, code 3 in IPv4, a different message from an echo reply. The errors don't provide enough information to identify an attack.
