Retro Forum

Personal learning projectNext.js · Prisma · SQLite

A forum project for learning how web application features, database access and authentication fit together.

Source code and setup instructions ↗

Goal and contribution

I developed the forum as a personal web application project, working with Next.js, Prisma and SQLite. The learning focus is understanding the relationship between the application, its data layer, authenticated users and administrative actions.

A practical challenge

This was my first experience with Prisma. Initial database integration caused a problem that I worked through with AI assistance. The useful learning topic was the database workflow and its connection to the application.

Implementation overview

AreaImplementation visible in the repository
Data layerPrisma with SQLite for application data.
Authenticationbcrypt password checks and signed JWT sessions stored in cookies.
Login attempt handlingPer-IP request limits and per-account failed-attempt tracking.
Current user lookupUser and role information is read from the database when resolving the current user.

Evidence and verification scope

The evidence for this write-up is the public source and README at commit c04b6df. The implementation was inspected for this summary. A runtime test report and public deployment are not included.

Before treating the application as deployment-ready, the useful checks are successful and failed login, rate-limit responses, unauthorized administrative access, logout and session behaviour. These are proposed checks rather than recorded passing results.

Trade-offs and next steps

The repository documents in-memory IP rate limits. A deployment across multiple application instances would need shared enforcement. Automated smoke tests and a reproducible note about the Prisma issue would make future changes easier to verify.

This project demonstrates work with a database-backed application and authentication code. A production security review is a separate activity.
